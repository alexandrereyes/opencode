# Session tools

`sessions/` registers the Code Mode namespace `sessions`: fourteen tools that read and control Alexandre's sessions as the
app lists and their controls do. Any agent may call them as `tools.sessions.<name>` inside `execute`; the Mestra
(`docs/master-session.md`) is their main user and its instructions name each one by its exact path and input keys.
They were the Mestra's own `tools.mestra.*` controls and the separate `tools.opencode.session_read` until 2026-10-30
(`docs/custom-master-session.md`, "Session tools outside the Mestra").

Former names were `tools.mestra.<name>` (before that `tools.opencode.<name>`) except `read`, which was
`tools.opencode.session_read`. Their tool IDs, and so their permission actions, are now `sessions_<name>`
(`sessions_list`, `sessions_read`, …); no configuration, test or plugin rule named the former IDs
(`mestra_*`, `opencode_session_read`). `sessionTool(name)` maps a call name in any of these forms (Code Mode path,
tool ID, former name) to the current short name, and never a bare native name such as `read` or `search`; the Watch
narration (`watch/delegation.ts`) and the apps' voice narration (`VoiceMasterProgress` in `OpenCodeKit/Voice.swift`) use
the same mapping, so transcripts and servers from before the rename still narrate.

## Catalog

All tools use Standard Schema inputs and outputs. Only `read` is `pinned`, listed in every session's catalog: it is the
session tool other agents use routinely (the apps' session mentions name `tools.sessions.read`), and as
`opencode.session_read` it fitted the budget of every measured catalog. The others compete for the 2,000-token inline budget, so another agent's
catalog shows the namespace and the few listings that fit, and `search` finds the rest. Measurements:
`docs/custom-master-session.md`.

## Targets and callers

Controls target only nonarchived top-level sessions, excluding the caller and Mestra sessions; the only exception is a
pending request owned by a subagent, accepted when its top-level ancestor is a valid target. The caller is the calling
session's top-level ancestor: a subagent acts for its whole family, so it cannot interrupt, archive, wait on or message
its own root, nor answer a request of its own family. No deletion is exposed: archive is the destructive limit.

`send` and `create` tag the admitted user prompt with its origin: `{"custom.master":{"sessionID":"<origin>"}}` when the
Mestra sends it (the apps label it "Sessão mestra"), `{"custom.sender":{"sessionID":"<origin>","agent":"<agent>"}}` for
any other agent (the apps show a plain user message).

Every executor receives an explicit `SessionsContext` (session, request, message, permission, VCS, worktree, model,
agent, preferences, managed chats and a small `git switch -c` runner), which the tests replace with fixtures.

## Inventory and attention

`sessions/inventory.ts` builds one snapshot per call from every top-level session (archived included, Mestra sessions
excluded), `session.active`, `request.pending`, the shared pins and mutes from `custom.preferences`, and the managed
chats root. Running sessions and request owners that are subagents are walked up their `parentID` chain once, so a
root's state and pending counts include its whole family, exactly like the app lists:

- **unread**: the navigation rule (`navigation/index.ts`): `time.idle > time.viewed` and either a newer completion or a
  `succeeded`/`failed` outcome. **failed**: `outcome === "failed"` and not viewed since.
- **state**: `needs-you` when the family has a pending question or permission, else `running` when the root or a
  descendant runs, else `idle`.
- **project**: grouped by `projectID`; the name is the basename of the main checkout (the directory with a `.git`
  directory), else the directory with most sessions. Managed chats collapse into one **Conversas** entry.
- Times are also rendered as pt-BR relative strings (`lastActivityAgo`) so answers never do epoch arithmetic.

The Live Activity (`live-activity/`) reads the shared pins and mutes through the same `marksFrom`.

## Tests

`test/sessions.test.ts` covers boundaries, root/self/archive/subagent filters with their reasons, calls from another
agent's session and from a subagent (lists without the caller, origin metadata, refusals for the caller's own family),
the namespace and the pinned `read`, the name mapping, family-aware state and counts, unread/failed rules, list filters,
projects, status (reply, error, files, subagents, cost), search, subagent requests and answers, model/agent validation,
standalone chats, worktrees with branch and their cleanup on failure, update (rename, model, agent, pins/mutes across
server keys), mark read, archive, bounded output and the virtual-clock wait timeout. Core's
`test/tool-opencode-session-read.test.ts` loads the plugin from source and as the minified release bundle, reads durable
cross-project pages through `tools.sessions.read` and checks that unloading the plugin removes it. `test/watch.test.ts`
checks the narration under current and former names.
